# HelmetGuard 2.1.0

基于 `arena/01a0f73c-helmetguard` 的 `5067615`，保留原架构迭代。
本仓库没有云端 API 服务；本次“后端配合”指 Android 后台服务与 ESP32 BLE。
附件描述的 `helm_alarm.ino` 实际文件未随附，本次没有替换用户设备上的固件。

## 修复与升级

- 事故列表的字面 `%` 不再进入数字格式串，修复已有事故记录时切换页面崩溃。
- 事故详情随数据库更新，中文区分等待确认、定位、提交运营商、部分成功及送达回执。
- 保存固件 deviceId/eventId 和设备地址，数据库唯一约束去重；先持久化再 ACK。
- 手机确认安全时用原固件 eventId 发送 Cancel；设备不在线时提示使用头盔长按。
- 手机算法已触发时可接收同次硬件确认；不同硬件事件保留独立身份，不强行当成同一事故。
- 真实与模拟检测器、记录来源隔离；真实事故优先于演练。恢复模拟事件也不会调用真实定位/短信。
- COUNTDOWN 阶段才能取消，等待处理任务退出后更新状态；短信开始发送后不再承诺撤销。
- 全量短信发送计划先原子落库；进程在发送中断后核对已有回执，避免盲目重复群发。无法确认的分段标为超时，提示人工求助；不承诺短信平台层面“恰好一次”。
- 事故结束后恢复检测，记录失败不会挡住事故触发；后台异常提供可见反馈。
- FFF1/FFF2 分别重组分片，防止两个特征交错破坏帧。序号统计处理重复、回绕及迟到帧。
- 记录计数和切换会话使用互斥，避免并发丢计数；CSV 在 IO 线程写入，分享失败提供提示。
- 定位超时保留本轮较差但有效的定位结果，历史位置最多接受 5 分钟；短信注明历史坐标时间。
- 事故倒计时覆盖全部页面，提供大尺寸安全取消按钮。卡片细边框、状态颜色对比、中文设备状态、指标单位布局和可滚动弹窗统一调整。
- 删除紧急联系人需要再次确认，设备断开时不再把旧健康帧显示为当前通过。

## 兼容与安装

- 版本 `2.1.0` / versionCode `30`；最低 Android 8，目标 Android 15。
- Room 数据库从 2 升到 3，只增加可空硬件字段与唯一索引；既有联系人、记录与事故保留。旧事故的硬件身份无法追溯补齐。
- CRC、消息类型、单位缩放、按键含义、ACK/Cancel 线格式保持协议兼容。
- CI 产物为可安装的 Debug APK，包名 `com.helmet.guard.debug`。它使用 CI Debug 签名；能否覆盖旧安装取决于旧包名及签名。若签名不同，请先保留旧应用和数据，另行用原签名构建，勿为升级直接卸载丢失资料。
- 正式版签名仍由用户原有安全配置提供，不伪造正式签名。

## 自动验收

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew connectedDebugAndroidTest
```

新增回归覆盖：事故格式化、协议 unsigned ID 与命令字节、序号统计、Android 35 事故列表与详情刷新、全局倒计时取消、硬件重发去重及 ACK 时机、恢复 Cancel 身份、模拟恢复隔离、迁移保留数据、记录来源和并发计数。
最终运行结果以此分支对应的 GitHub Actions 报告为准。

## 尚需实机验证

1. 使用附件所述实际固件验证配对、FFF2 Indicate、ACK 停止重发、Cancel 停鸣和重连。
2. 在 MTU 保持 23 时验证实际固件分片。App 可重组分片；仓库参考固件整帧直接通知，不能仅凭 App 测试声称默认 MTU 的端到端降级已通过。
3. 华为/国内 ROM 锁屏、权限撤回、开机恢复、后台定位和真实双卡运营商回执。
4. 实际 IMU 标定、误报率、漏报率及断连后硬件独立报警。模拟器与固定向量不能替代这些结果。

## 对原竞技场实现的评价

值得保留：模块边界清楚、无 GMS 定位选择合理、协议有跨语言固定向量、考虑了 Room 迁移和短信提交/送达区别，原有云端编译和单测也确实通过。

主要短板是运行流程验收：有记录的事故页没有被实际点过，ACK 早于持久化，Cancel 未接到固件，模拟和真实共用有状态检测器。测试手册里列出的目标也不能当成已经完成的测试证据。这些问题对安全类应用比页面能编译更重要。

结论：适合继续用来做架构、界面和初稿，也有实用的工程能力；关键业务仍需独立审查、自动回归与实机联调。未知原模型身份和当时完整提示，不能用这一个项目判定它与另一模型整体水平相同或高低。本次修复同样应接受这些验收标准。
