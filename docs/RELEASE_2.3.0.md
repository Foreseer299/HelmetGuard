# HelmetGuard 2.3.0

2026-11-03 · Android 12+ · ARM64 · 内部评估调试版

## 本次修复

- 首页蓝色渐变守护卡恢复 2.1 的 HealthAndSafety 盾牌图标；其余现有界面风格保留。
- 通讯提醒改为独立服务，不要求先开启头盔传感器守护。普通用户为短信＋来电；骑手额外处理用户选择的接单应用通知。
- 新增默认关闭的“手机测试播报”：仅用于无可用头盔时在手机上测试。兼容头盔音频就绪后优先头盔。未开启测试且无头盔时明确显示未播报原因。
- 来电可选简短提醒、播报来源；短信可选简短提醒、播报来源、仅朗读系统通讯录联系人的简短正文。无联系人授权或无法匹配时降级，不朗读陌生正文。
- 根据默认短信/拨号应用通知的 Person 号码、联系人 URI 或唯一通讯录姓名在本地查询；不将项目紧急联系人当成手机通讯录，不持久化通知原文或姓名。
- 验证码数字、隐藏正文不朗读；多条 MessagingStyle 会话仅取最新消息与对应发送者；无法分离多条历史文本时不读正文。
- 来电状态与通知身份合并；接听、挂断、停用来源、改变隐私选项和事故状态会撤销当前普通播报。重叠双卡无法可靠关联时不猜姓名。
- 最近播报区与诊断分开报告捕获、过滤、合成、手机实际播放完成及头盔结果，不把入队显示为播放成功。

## 安装与使用

本包 `com.helmet.guard.debug`，versionCode 50，与已交付 2.2 alpha04 签名一致，可覆盖更新。旧 2.1 签名不同，需先卸载；用户已确认无需保留旧记录。

进入“设置 → 通知与头盔语音”：启用通讯提醒、授予系统通知使用权；电话状态用于接听/挂断撤销，通讯录权限用于已存联系人匹配。无头盔测试时另开“手机测试播报”，测试后关闭。通知来源须是默认短信/拨号应用；系统未提供的通知正文不能恢复。

详细步骤见 [手机与头盔指南](PHONE_AND_HELMET_TEST_GUIDE.md)，证据见 [测试记录](TEST_RESULTS_2.3.0.md)。

## 交付边界

实体硬件协议仍待同学提供，本次未改动 2.2 alpha04 的参考固件与协议。模拟器通知和 AudioTrack 消费回执不等于真实运营商短信、realme 锁屏/双卡或头盔扬声器验收。头盔联调按 `BLE_PROTOCOL.md` 与 `AUDIO_PROTOCOL_V1_DRAFT.md` 核对。

APK 内离线 TTS 候选权重授权仍待确认，仅内部评估；源码与公开分支不包含模型权重、运行库 AAR 或签名私钥。见 [第三方 TTS 说明](THIRD_PARTY_TTS.md)。
