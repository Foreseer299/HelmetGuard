# HelmetGuard 2.1 界面与动效设计指导

本轮由主代理制定设计约束，交给 GPT-6.1 Sol 实施，再独立审查与验证。适用于现有原生 Android Compose 应用。

## 视觉方向

保持清晰、可信的骑行工具气质。蓝色用于品牌与主要操作，青色用于辅助信息，绿色表示确认就绪，橙色表示待处理，红色只用于紧急事件和失败。状态必须同时有文字，不能只靠颜色。

- 浅色：冷白背景、白色卡片、深蓝正文、柔和边框；深色：深蓝背景、略亮卡片、足够亮的文字与状态色。补齐 Material 配色角色，消除默认紫色导航背景和突兀青色选中态。
- 使用统一 4/8 dp 间距节奏，页面左右 18–20 dp，卡片 20–24 dp 圆角。正常操作触控区至少 48 dp，紧急取消按钮至少 56 dp；按钮采用最小高度，支持大字体换行。
- 头部保持一个主标题和一条有用说明。首页先读到守护状态和操作，再读数据；缩减大渐变卡与四个指标卡的竖向占用。淡色装饰可使用原生 Canvas/矢量图形，不增加网络图片、字体或位图依赖。
- 数值与单位层次分明，保持对齐；无数据保留 `--`，离线/未启动不能显示成“安全监测中”。事故置信度不是事故概率，避免给予错误确定感。
- 设备、数据、记录、设置复用同一套标题、卡片、空状态和状态标签；空状态说明下一步。事故阶段、短信“已提交/已送达”的区别及模拟标识继续明确。

## 动效规则

|场景|设计要求|
|---|---|
|一级导航|约 160–220 ms 淡入淡出，可有不超过 8 dp 位移；不要全屏大幅滑动或弹簧反弹|
|按下操作|保留 Material ripple，交互立即响应；不强制延时，不拦截重复触摸来播放动画|
|状态变化|约 180–240 ms 颜色/内容过渡；标签布局稳定，避免不断闪动|
|折叠与展开|仅对低频内容使用尺寸过渡；不要对整页或实时遥测卡逐帧重排|
|倒计时|依据事件的真实剩余秒数绘制确定进度，事件更换重置；数字直接更新，圆环可短时平滑；没有额外视觉计时器，不改变发送时机|
|紧急操作|立即显示，取消和立即求救一直可点；不闪屏、不持续脉冲、不依赖动效传递状态|
|实时数值/曲线|按实际样本更新，不做数字滚动、延迟插值或装饰性扫描，避免数据失真与耗电|

所有动画使用 Compose 的系统动画时长缩放机制；系统禁用动画时应立刻呈现目标状态。不要循环背景动画、粒子效果、假加载、额外振动或声音。导航动画不能包含或推迟全局事故弹窗。

## 实施边界

本轮仅修改 UI、相关 UI 测试、版本信息与文档。保留 Room 迁移、BLE V1、硬件身份去重、落库后 ACK、Cancel、模拟隔离和短信回执语义。不新建服务，不变更协议或后端接口。沿用 `release/2.1` 分支与现有 PR，版本更新为 2.1.1 / 31，便于识别新安装包。

## 验收

1. 原有 JVM 与 Android 事故回归继续通过，lint 无新增错误。
2. 输出浅色、深色首页，以及设备/记录空状态、事故详情、倒计时的真实模拟器截图。
3. 覆盖 320 dp 宽度与放大字体，确保重要文字可读、动作可滚动到且没有硬裁切。
4. 导航后仍能触发与取消全局倒计时；重组/事件更新不重启动画计时，不触发真实短信。
5. 有动画与关闭动画两种情况下检查倒计时/导航终态与按钮可用性；静态截图不等于动画流畅度验收。实体设备帧率和系统后台行为另行实测。
