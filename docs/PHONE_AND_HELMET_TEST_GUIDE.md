# 手机与头盔联调指南

本指南用于后续测试，**不表示真机或头盔已经验收**。目前以项目内默认参考协议为暂定基础；同学的实际头盔协议、硬件和固件尚待确认。联调前记录 App 版本、手机型号与系统版本、固件版本和测试时间。

## 手机设置与试听

1. 安装 HelmetGuard 2.3.0 APK（包名 `com.helmet.guard.debug`）。与已交付的 2.2 alpha04 签名一致，可覆盖安装；历史 2.1 签名不同，需要先卸载。进入“设置 → 通知与头盔语音”，启用“通讯提醒”。它有独立的前台通知，无需开启头盔传感器守护。
2. 打开系统通知使用权并授权 HelmetGuard。允许普通通知和电话状态权限，来电才可按接听/挂断状态及时撤销。短信通过系统默认短信应用的通知获取，不读取短信数据库；默认短信应用必须正常发布通知。系统隐藏、脱敏或禁止给监听器提供的内容无法恢复。
3. 普通用户仅处理短信和来电；骑手模式增加用户自行勾选的接单应用通知。来电可选“简短提醒”或“告诉我谁来电”。短信可选“简短提醒”“告诉我谁发来的”或“通讯录联系人的内容”。第三项需要通讯录权限，按系统通讯录匹配；陌生短信、无法确定身份、验证码、隐藏正文只报来源或提醒，不读验证码或陌生正文。
4. **未连接兼容头盔时验证手机出声，需额外打开“手机测试播报”。此开关默认关闭，仅用于测试。** 有兼容且可用的头盔时优先发往头盔；测试开关不表示头盔已经通过验收。测试完关闭。手机播报遵守媒体音量和音频焦点；不会强行调大系统音量。
5. 在“离线 TTS 音色”选择自动或可用离线音色，可先点“在手机上试听离线音色”。试听和通知自动播报是两条不同入口，应分别检查。实际测试包包含待确认权重授权的内部评估音色，不用于公开发行。
6. realme 的设置名称随系统版本变化：在应用管理允许自启动、后台活动和通知，电池设置允许后台运行；如系统支持，可在最近任务锁定应用。返回应用查看通讯服务和通知监听状态，随后用另一台手机分别发送测试短信和拨打电话。检查联系人、陌生来源、验证码、锁屏、接听和挂断，不要触发真实求救短信。请勿以本机其他应用生成的通知替代默认短信应用来测试 SMS 来源。
7. 在“最近播报”同时检查捕获/过滤结果和实际播放状态。未开启手机测试且无兼容头盔时，会明确说明未播报；不要把“已入队”当成已播放。无法提醒时导出诊断 ZIP，附上触发时间和版本。

## 模拟器验证范围

2.3 在独立 Android 12 模拟器使用仅供测试的默认短信/拨号器夹具，由 Android NotificationManager 发布通知，经过真实 NotificationListenerService、通讯录查询、策略、离线合成和 AudioTrack 播放完成回执。来电身份来自真实测试通知，电话 RINGING/IDLE 由测试注入；不是运营商通话。测试夹具源码位于 `test-fixtures/communication`，不可在用户手机安装或设置为默认短信/拨号器。

具体通过数及证据见 `TEST_RESULTS_2.3.0.md`。模拟器结果不代表 realme 的真实双卡、锁屏后台、运营商收发、蓝牙链路或头盔扬声器已经验收。

## 后续真实头盔测试

1. 先与同学核对实际硬件和协议：BLE 服务/特征 UUID、读写及订阅属性、加密配对、MTU、分片、事故 ACK/取消、音频格式、状态码与版本。项目参考安全服务是 FFF0–FFF3，音频草案是 `8F7A0000–0004`；这些只是参考，不能假定同学设备兼容。协议细节见 `BLE_PROTOCOL.md` 和 `AUDIO_PROTOCOL_V1_DRAFT.md`；文档描述需与实际运行版本逐项核对。
2. 在安全台架确认供电、电气连接、共地及功放/扬声器接线，确认固件版本与音频能力；不要将未固定的实验硬件用于道路骑行。将手机与设备靠近，授予附近设备等必要权限，在设备页面扫描、配对并连接，记录协商 MTU、连接状态和实际能力。连接成功不等于音频输出成功。
3. 使用双方确认的测试通知，分别验证短信、来电和选中骑手 App 通知，观察头盔实际声音、内容、音量与延迟；同时观察断连、重连和锁屏后的表现。无音频输出时检查设备能力、接线和协议，不将手机试听当作头盔播放。
4. 在受控台架与同学约定测试事故事件、ACK/取消以及播报期间事故抢占；记录时间和实际现象，避免触发真实短信求救。再按双方协议测试较小 MTU、加密连接、丢包或中断恢复。上述各项均须独立实测，状态报告或软件构建通过不等于扬声器确实发声。

## 诊断与反馈

复现问题后，在“设置 → 通知与头盔语音 → 诊断”点击“导出脱敏诊断 ZIP”，通过系统分享界面保存或按需要交给测试人员。页面说明默认不包含通知正文、姓名、电话、地址、密钥或音频；分享前仍应自行检查内容，尤其是可能包含的崩溃信息。附上版本、realme 系统版本、模式、触发步骤、时间、预期和实际结果；涉及头盔时补充固件、协议版本、连接状态和 MTU。不要附真实手机号、通知正文或配对凭据。
