# 手机与头盔联调指南

本指南用于后续测试，**不表示真机或头盔已经验收**。目前以项目内默认参考协议为暂定基础；同学的实际头盔协议、硬件和固件尚待确认。联调前记录 App 版本、手机型号与系统版本、固件版本和测试时间。

## 手机设置与试听

1. 安装 HelmetGuard 2.2 APK（包名 com.helmet.guard.debug）。本包签名与先前 2.1 不同，用户已确认不需保留记录：首次安装前卸载 2.1；后续沿用同一签名的 2.2 测试包可以覆盖更新。，打开“设置 → 通知与头盔语音”。在“使用模式”中自行选择：**普通用户**处理短信和来电；**骑手**处理短信、来电及所选接单应用的工作通知。打开“启用骑行播报”，并按需要打开“来电”“短信”。正式的头盔播报还需要守护开启、头盔连接和音频能力可用。
2. 点击“打开通知使用权”，在系统页面允许 HelmetGuard，返回后确认页面显示已授权。测试来电等功能时按系统提示授予相应权限；不要通过真实紧急求救验证普通播报。
3. 骑手模式下点击“选择接单应用”，勾选已安装的实际骑手接单 App，并打开“骑手应用”；按需调整骑手事件和收益播报。普通用户模式无需选择接单应用。测试通知时分别检查已选、未选应用，以及短信和来电；记录实际结果，不把未选应用收到通知视作应播报。
4. 在“离线 TTS 音色”查看系统离线音色或应用内音色状态，选择自动或可用音色，点击“在手机上试听离线音色”，调整语速、音调和手机媒体音量。手机试听只验证手机本地合成与扬声器，不能证明头盔可播。可在断开网络后再试听并记录结果；若无可用音色，先检查设备系统语音与所安装测试包的音色状态。
5. realme 的设置名称随系统版本变化：在应用管理中允许 HelmetGuard 自启动和后台活动，在电池设置中选择不优化或允许后台运行；如系统支持，在最近任务中锁定应用。检查通知权限和持续监测前台通知，锁屏一段时间后再测试。强行停止、蓝牙关闭或系统回收进程都可能中断连接，后台设置不能保证永久运行。

## 模拟器能检查什么

模拟器可用于检查页面、模式切换、通知使用权入口和可用的手机试听流程。模拟器的 SIM、通话、通知、音色、蓝牙和后台策略可能与 realme 不同；模拟器结果不代表真实双卡、锁屏后台、头盔连接、音频播放或事故抢占通过。需在实际手机上另行记录。

## 后续真实头盔测试

1. 先与同学核对实际硬件和协议：BLE 服务/特征 UUID、读写及订阅属性、加密配对、MTU、分片、事故 ACK/取消、音频格式、状态码与版本。项目参考安全服务是 FFF0–FFF3，音频草案是 `8F7A0000–0004`；这些只是参考，不能假定同学设备兼容。协议细节见 `BLE_PROTOCOL.md` 和 `AUDIO_PROTOCOL_V1_DRAFT.md`；文档描述需与实际运行版本逐项核对。
2. 在安全台架确认供电、电气连接、共地及功放/扬声器接线，确认固件版本与音频能力；不要将未固定的实验硬件用于道路骑行。将手机与设备靠近，授予附近设备等必要权限，在设备页面扫描、配对并连接，记录协商 MTU、连接状态和实际能力。连接成功不等于音频输出成功。
3. 使用双方确认的测试通知，分别验证短信、来电和选中骑手 App 通知，观察头盔实际声音、内容、音量与延迟；同时观察断连、重连和锁屏后的表现。无音频输出时检查设备能力、接线和协议，不将手机试听当作头盔播放。
4. 在受控台架与同学约定测试事故事件、ACK/取消以及播报期间事故抢占；记录时间和实际现象，避免触发真实短信求救。再按双方协议测试较小 MTU、加密连接、丢包或中断恢复。上述各项均须独立实测，状态报告或软件构建通过不等于扬声器确实发声。

## 诊断与反馈

复现问题后，在“设置 → 通知与头盔语音 → 诊断”点击“导出脱敏诊断 ZIP”，通过系统分享界面保存或按需要交给测试人员。页面说明默认不包含通知正文、姓名、电话、地址、密钥或音频；分享前仍应自行检查内容，尤其是可能包含的崩溃信息。附上版本、realme 系统版本、模式、触发步骤、时间、预期和实际结果；涉及头盔时补充固件、协议版本、连接状态和 MTU。不要附真实手机号、通知正文或配对凭据。
