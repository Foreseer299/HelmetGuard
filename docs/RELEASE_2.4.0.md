# 2.4.0：设备、记录与设置重构

发布范围：Android 应用、使用说明、GitHub 默认主页。保持首页“守护”和第三页“数据”的源码、共享主题与原组件不变。本次不修改固件协议，不声称补齐尚未收到的实际硬件协议。

## 操作结构

- 设置成为分类入口：紧急联系人、短信发送与无障碍、求救资料与倒计时、通讯与语音、权限与后台运行。
- 短信确认辅助在独立页面顶部展示连接状态、开启方法与作用范围，不再隐藏在长页末尾。测试前有费用及收件人确认；离开子页会取消尚未提交的延时测试。
- 通讯分成来电、短信、接单、声音、诊断子页。手机播放仍是独立的测试开关；姓名与正文权限仍依手机通讯录判断。
- 音色引擎仅进入声音页时创建，离开时释放；音量和语速等参数在拖动结束后保存，减少连续修改对播报的干扰。
- 联系人支持号码格式整理、重复号码与短号检查；发送顺序统一为 1–100。操作失败会保留编辑内容，删除前确认。
- 设备页区分扫描、连接准备、正常连接和数据中断；查找、校准、忘记设备都有说明，重要操作先确认。
- 记录页可选择是否包含演练；删除前确认，导出时阻止重复提交，详情显示实时数据及读取失败状态。

## 技术修补

- BLE 连接准备超过 20 秒仍未完成时进行恢复；GATT 操作超时后关闭旧连接，避免迟到回调被当成下一次操作完成。
- 连接代次与计时器校验、迟到扫描失败保护；扫描不再覆盖活动连接状态，主动断开会停止扫描。
- 连接后一直没有遥测也会标为数据中断，设备检查不再使用上次连接的陈旧数据。
- 权限被撤销时清理蓝牙连接，系统调用失败时保留可理解的错误状态。
- 定位时效优先采用单调时钟，避免修改系统时间影响旧位置判断；取消后不会再注册遗留监听，粗略定位也能配合定位前台服务。
- 录制中的详情读取先刷新缓冲；删除和录制切换串行执行，避免误停另一条录制。

## 验证与边界

本次实测：JVM 单元测试 73/73 通过；Android 12/API31 的导航、联系人、删除确认、录制缓冲、事故、短信回执、权限撤销、音频生命周期及小雅合成共 25/25 通过；重新授权后通讯完整链路 7/7 通过。Debug APK 与测试 APK 构建成功，Lint 0 errors / 60 warnings（含既有警告）。

首页、第三页数据、原共享主题和原组件与 2.3.4 对比无源码差异。APK签名与2.3.x一致；无数据库迁移或清空。

升级安装后曾复现通知权限已授权但监听未绑定，首轮通讯测试一项超时。关闭再开启通知使用权后恢复；该行为作为实测限制保留，没有宣称应用可以自行修改系统授权。页面显示实际监听状态和恢复办法。

模拟器覆盖联系人保存、子页导航、短信测试取消、记录删除、录制缓冲、事故流程、音频合成、通知捕获与PCM播放。它不能证明真实蜂窝发送、各品牌锁屏确认、实体蓝牙连接恢复和扬声器输出；这些仍需真机验收。

内置小雅离线方案与模型卡边界沿用 2.3.4，见 [TTS 来源说明](THIRD_PARTY_TTS.md)。无障碍不代替身份验证、解锁或永久授权，只在用户启用后处理符合限定条件的本应用短信确认。
