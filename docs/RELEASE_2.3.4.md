# HelmetGuard 2.3.4：通讯与求救链路维护

2026-11-11，北京时间。以 2.3.3 为基础的局部技术修补，保留守护首页、设备、数据、记录页面的视觉设计。设置中的权限详情、厂商后台指引、事故策略和语音参数按需展开。

## 实际修复

- Android 12+ 同时请求精确和粗略定位，避免部分系统忽略只有精确定位的请求。返回系统设置时重新检查权限与 SIM；撤销蓝牙权限不再让可靠性检查抛出异常，同时检查扫描与连接两项权限。
- 所选 SIM 失效不再静默改用另一张卡。短信的提交结果与送达结果分开处理，送达报告解析 GSM/CDMA 状态，不把广播 `RESULT_OK` 等同于收件人已收到；临时失败与缺失报告保持未确认。
- 无障碍辅助在解绑时清理状态，支持文字嵌在单子节点按钮容器内的系统确认框，回收 Android 12 的窗口节点。仍需用户主动启用；仅处理 HelmetGuard 自己本次发送、可信系统来源、明确标题及唯一发送/取消按钮，不自动授权、验证身份或解锁。
- 重复来电通知保留原始可撤销记录；接听/挂断、停用来电或权限撤销后撤销待播报内容。排除拨出、通话中和未接来电通知。定期重新检查 SIM 与电话权限，避免不停重复注册。
- 事故状态直接更新播报安全门控；清空队列也使旧合成失效，防止合成完成后又播出已撤销内容。
- 系统 TTS 合成最多等待 6 秒，失败或超时回退内置音色；外部取消不触发兜底播放。试听与正式手机播放共用 PCM 路径，处理音频焦点、撤销和实际播放完成，手机测试也遵守音量设置。
- 内置推理引擎在后台释放，避免退出页面时等待原生合成而卡住主线程。TTS 超时/失败有明确状态，试听不再把“提交请求成功”当成“播放完成”。

## 跨机型处理原则

使用 Android 的权限、前台服务、通知监听和短信 API 作为公共路径；厂商后台入口只提供可失败回退的引导。Huawei/荣耀、小米/Redmi、OPPO/一加/realme、vivo/iQOO、三星以及其他 Android 的实际版本菜单和限制仍由系统决定。

“已授权”“辅助已绑定”“运营商接受发送”“网络确认送达”是不同状态；不会因为开启一个开关就报告全部功能正常。先做亮屏测试，再做锁屏延时测试。无障碍仅适配符合识别条件的窗口，并非所有 ROM 的通用绕过工具。

## TTS 方案判断

继续使用现有量化小雅离线模型：模型本体约 19 MB，默认无网络依赖，适合短中文提醒。保留用户主动选择的系统离线中文音色。此次修复集中在超时、取消、释放和播放一致性，没有再次更换音色。内置模型不支持音高调节；原生推理不能强制中断，取消后丢弃结果并停止播放。来源及非商业模型卡边界见 [THIRD_PARTY_TTS.md](THIRD_PARTY_TTS.md)。

## 验证边界

验证结果：
- JVM 单元测试 66/66 通过。
- Android 12 / API 31 模拟器：权限撤销、短信失败 PDU 回执、短信实测取消、音频生命周期、事故恢复与抢占、内置音色真实合成，共 12/12 通过。
- 使用独立短信／拨号通知夹具，经真实 Android 通知监听、通讯录查询与 PCM 播放验证：短信播放、通知移除后继续播报、验证码与隐藏通知、已存联系人正文、手机测试开关、来电挂断撤销、通知权限撤销及恢复，共 7/7 通过。夹具不发送运营商短信。
- Debug APK 与测试 APK 构建成功；Lint 0 errors、62 warnings（包含既有项），未宣称零警告。
- APK 使用与 2.3.3 相同包名和签名，可覆盖安装；versionCode 54。

模拟器不能证明真实蜂窝短信送达、不同厂商确认窗口、锁屏自动点击、双卡来电身份及头盔实机音频。来电姓名依赖系统拨号通知提供可核对的身份，缺失时只提示有来电。Android 15+ 对开机启动媒体前台服务有限制，重启后请打开应用确认通讯服务恢复。
