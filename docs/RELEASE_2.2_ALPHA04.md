# HelmetGuard 2.2.0-alpha04

本版由 Codex 接手外部工作区后完成基础功能和回归。用户确认：普通用户只处理短信、来电；骑手增加所选接单应用的通知。实际手机为 realme，实体头盔协议待同学提供，当前固件仅作为默认参考协议。

## 使用

版本 2.2.0-alpha04 / 43，Android12+、ARM64，包名 com.helmet.guard.debug。首次安装前卸载旧2.1（用户已确认不需保留数据）：旧2.1与本版签名不同，不能直接覆盖。之后使用本版同一调试签名的测试包可覆盖更新。本版沿用外部2.2评估包的调试签名；私钥不进入源码、交付ZIP或GitHub。

设置→通知与头盔语音：选择普通用户/骑手；开启通知使用权；骑手模式手动选择已安装的接单应用。默认不选择任何骑手应用。实际头盔播报仍需开启守护、授予相关权限、连接兼容头盔。没有头盔时可手机试听离线中文音色、测试通知分类并导出日志。

## 已完成

- 保留2.1主题和页面结构，新增两种模式及接单应用选择。
- 数据页明确显示加速度(g)、角速度(°/s)、倾角与姿态(°)；AX/GX改为分组下的X/Y/Z轴，无设备时倾角显示--。
- 通知来源精确白名单，普通用户拒绝骑手来源；来源开关与订单过滤/去重继续生效。
- Android请求MTU247，协商失败/未启动用默认23；补充短信包和TTS引擎可见性声明。
- 事故取消当前普通任务、清空队列，并用代次校验拒绝事故期间/事故结束后的迟到合成结果。高优先级通知可以取消低优先级任务；来电接听/挂断撤销已入队任务；双卡身份无法确定时不猜测。
- 合成有超时，TTS后和START前检查有效期；语音最长截取12秒。修复CRC调用在Android12上的API兼容问题。
- 相同缺块允许500ms后的有限重试，不会永久被当作旧NACK忽略。
- 固件音量参数实际作用于PCM；0静音，100单位增益，不放大溢出。固件以单调时钟执行接收期限。
- 固件区分DMA提交与最终排空：正常结束写入超过整圈DMA容量的静音，然后等待新TX_DONE再停止；正常完成不清空未播尾音。事故/断连通过代次和I/O锁阻止旧块恢复。
- 日志串联通知决策、合成耗时、BLE状态与最终结果；导出前等待日志写入，附连接/能力快照及去掉异常正文的崩溃堆栈。默认不存通知正文、号码或音频。日志最多3000条或7天，不能等同无限系统logcat。
- N16R8板定义已补齐，PlatformIO默认选N16R8音频环境。

## 验证及边界

见 TEST_RESULTS_ALPHA04.md。Android12容器验证真实系统通知→监听→分类入队、离线中文TTS生成PCM/ADPCM、模式切换、日志导出和既有事故/数据库回归。没有BLE实体外设，不把这些结果写成头盔已实播；MAX98357A供电/音量、电气接线、RF吞吐、事故到实际停声延迟、realme锁屏和真实双卡仍待实机。

固定提示音命令尚未实现，能力不足时记录明确失败，不承诺已具备本地提示音兜底。物理配对窗口和生产设备标签流程需在实际硬件协议确定后对接；参考固件的配对口令目前由串口初始化输出。语音模型仍沿用内部评估资源，权重许可未解决；请勿将该评估APK公开/商业分发。源码不包含权重或签名私钥，详见 THIRD_PARTY_TTS.md。
