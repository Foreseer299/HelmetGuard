# HelmetGuard 2.3.3 求救短信兼容

在“设置 → 求救短信实测”发送一条标有“无需救援”的普通测试短信。App 会显示收件人和尾号，使用已配置的求救 SIM，分别显示运营商提交回执和超时结果。

| 本机表现 | 如何设置 |
| --- | --- |
| 直接发送 | 保持原生短信发送，做一次锁屏收件测试。 |
| 出现“始终允许” | 先亮屏测试，在系统中选“始终允许”并完成身份验证。华为截图属于此类。 |
| 每次出现“发送”和“取消” | 在“管理短信确认辅助”打开系统设置并启用服务。在测试对话框中勾选“本次测试使用确认辅助”。realme 截图属于此类。 |

确认辅助默认关闭，与手机品牌无关。主动启用后，仅在本应用已经调用短信接口、求救倒计时已结束或已确认测试时处理。15 秒内打开的系统窗口须来自平台签名或具备系统电话权限的系统组件，并具有本应用的明确短信标题和唯一可见的发送、取消按钮。每个窗口只尝试一次，身份验证界面和未识别的窗口由系统保留原有行为。屏幕内容仅在本机即时判断，诊断记录发送请求、屏幕状态、回执和匹配后点击的系统组件，不含号码或短信正文。

勾选“延时 10 秒，测试锁屏发送”，确认后留在本页并熄屏。倒计时期间可取消，提交时手机须已熄屏。只有收件人在手机保持锁屏且无人手动点击的情况下收到短信，才算该次测试通过。系统可能在锁屏时隐藏确认界面，或提供不同的控件与文案。此时即使辅助已连接，仍需以实机收件结果为准。

验证覆盖 55 项 JVM 测试和 7 项 Android 模拟器用例。Android 12 系统已实际绑定该服务。JVM 测试覆盖确认文本、尝试时限、重复窗口及重叠请求。模拟器验证了测试入口、提交前取消、权限拒绝和事故流程回归。厂商真实弹窗点击和锁屏收件待各机型实测。
